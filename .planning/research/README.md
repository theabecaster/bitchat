## Key Findings

### Architectural Insight

**PTT is a streaming transport protocol, not a message type.**

Unlike fileTransfer (which batches data and sends after complete), PTT streams fragments continuously while a button is held. This drives the architecture choice:
- Separate **PTTService** owns streaming coordination
- **VoiceRecorder** in streaming mode (not batch) emits frames continuously
- **PTTAudioBuffer** (jitter buffer) reorders fragments in real-time
- Minimal **ChatViewModel** involvement (mostly property exposure)

### Build Strategy

**Phased, dependency-driven approach:**

1. **Phase 1 (weeks 1-2):** Protocol + Lock Mechanism
   - Define audio stream packet type (0x23)
   - Implement PTTChannelLock state machine
   - Modify BLEService for audio transport

2. **Phase 2 (weeks 3-4):** Streaming & Fragment Pipeline
   - VoiceRecorder streaming mode callback
   - PTTAudioBuffer (jitter buffer with reordering)
   - PTTService (main orchestrator)

3. **Phase 3 (weeks 5-6):** Playback & UI
   - AudioStreamPlaybackController
   - PTT button and indicators

4. **Phase 4+ (weeks 7+):** Polish
   - Level meter, waveform visualization
   - Directed PTT with Noise encryption
   - Adaptive jitter buffer

### Critical Constraints

- **Latency:** <200ms single-hop (drives streaming architecture, small jitter buffer)
- **Half-duplex:** First transmitter wins (protocol-enforced via PTT_START/END broadcasts)
- **No persistence:** Audio never logged, never stored on disk
- **Backward compatible:** Existing text/file transfer packet types unchanged

## How This Informs Roadmap

### Recommended Roadmap Structure

**Milestone: PTT v1 (MVP)**
- Phases 1-3 deliverables
- Broadcast PTT only (unencrypted)
- Single-hop focus (multi-hop routed by existing BLE mesh)
- No recording history, no directed PTT

**Milestone: PTT v1.1 (Polish)**
- Phase 4 enhancements
- Level meter, waveform
- Battery optimization

**Milestone: PTT v2 (Features)**
- Directed PTT (Noise encryption)
- Audio recording (optional)
- Advanced jitter buffer

### Phase Dependencies

```
Roadmap Phase X: [Build Phase 1 + 2 + 3 of PTT]
├─ Unblocks: Talk feature works end-to-end
├─ Risks mitigated: Protocol finalized, core services tested
└─ Polish in Phase X+1: Level meter, directed encryption

Roadmap Phase X+1: [Build Phase 4 of PTT]
├─ Unblocks: Production-ready UX
└─ Risks: Minimal, core feature complete
```
